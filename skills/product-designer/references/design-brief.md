# Design brief

A brief describes a screen. It is not code and not a Lovable prompt.

## Shape (one page)
- Goal and user: who, what they are trying to do, what changes for them.
- What changes: the specific difference from today.
- Layout and hierarchy: what is most prominent, and in what order things read.
- Copy: the exact words for headings, buttons, and helper text.
- States: empty, loading, error, and the odd case.
- Avoid: what not to do, and why.
- How we will know it worked: one observable check.

## Saving
- Save as a new file in the project's `design/` folder, named with a date and the topic. Never overwrite.

## Throwaway prototype (only if asked)
- One HTML file with CSS and JS inline, no frameworks, sized for desktop unless the owner says otherwise.
- Save in `design/prototypes/`. Prototypes are for deciding, not shipping.
